# 各家手机读取电池数据的差异

## 结论

差异非常大，而且**不只出在权限层面**。同一个品牌换一颗芯片平台（骁龙 / 联发科），表现可能完全不同。所以按品牌写 `if` 分支一定会过时，本项目的做法是按**能力**探测。

## 差异分四层，越往下越隐蔽

| 层级 | 差异内容 | 后果 |
|---|---|---|
| 一、有没有 | HAL 根本不提供这个字段 | 读到 0 或 `Int.MIN_VALUE` |
| 二、单位 | 文档写 µA，实际给 mA | 差 1000 倍，显示 `0.0 W` 或 `63000 W` |
| 三、符号 | 充电时电流为正还是负 | 取绝对值才安全 |
| 四、能不能读 | SELinux 是否允许读 sysfs | 节点存在但 Permission denied |

还有两个容易忽略的：

- **双电芯**：分成主/从两个节点，是加总还是只取一个，各家不同。
- **后台冻结**：国产 ROM 会冻结后台进程，Pixel / 三星相对宽松。

## 品牌对照

> 只标注「实测」的是我在 OPPO Find X8s（联发科平台，Android 16）上逐项验证的；其余是社区常见表现，未经我逐一核实，请当作线索而非结论。

| 品牌 / 平台 | `CURRENT_NOW` 单位 | `EXTRA_VOLTAGE` | `/sys/class/power_supply` | 已知坑 |
|---|---|---|---|---|
| **OPPO / 一加 / realme** | **mA（实测）** | **垃圾值 `4`（实测）** | **全部封禁（实测）** | SVOOC 私有协议，双电芯 |
| Google Pixel | µA（标准） | 正常 mV | 多数可读 | 最接近 AOSP 参考实现 |
| 三星 | µA | 正常 mV | 部分可读 | 符号：放电为负；部分机型恒定 0 |
| 小米 / Redmi | 骁龙 µA、联发科 mA | 多数正常 | 基本封禁 | 私有 extra：`max_charging_current` |
| vivo / iQOO | 常见 mA | 常见正常 | 基本封禁 | FlashCharge 私有协议 |
| 华为 / 荣耀 | µA（部分 mA） | 常见正常 | 基本封禁 | SCP / FCP 私有协议 |

## 本机实测记录

在 OPPO Find X8s（`PKT110`，联发科，Android 16）上逐项验证的结果：

| 探测项 | 返回值 | 判定 |
|---|---|---|
| `BATTERY_PROPERTY_CURRENT_NOW` | `-1318` | 负数表示充电中；绝对值 1318，单位是 **mA**（即 1.318 A） |
| `BATTERY_PROPERTY_CURRENT_AVERAGE` | `Int.MIN_VALUE` | 该属性不存在 |
| `BATTERY_PROPERTY_ENERGY_COUNTER` | `Int.MIN_VALUE` | 该属性不存在 |
| `EXTRA_VOLTAGE` | `4` | 无意义值，正常应为 4400 左右（mV） |
| `dumpsys battery` 里的 voltage | `4` | 框架层本身就是坏的，不是应用读错 |
| `/sys/class/power_supply/` | `Permission denied` | SELinux 封禁，连 `ls` 都不行 |

`adb shell` 用 shell 用户身份可以读，这是系统给调试通道开后门，普通应用没有这条路：

```
usb 节点（输入侧）：  4.93 V × 0.85 A ≈ 4.2 W
battery 节点（电池侧）：4.47 V × 0.79 A ≈ 3.5 W
```

差额 0.7 W 是屏幕和系统自身消耗。**这证明 `/sys` 里确实有输入侧功率，但普通应用拿不到。**

## 兼容策略：按能力分支，不按品牌

本项目代码里没有任何一处判断 `Build.MANUFACTURER`，全部靠探测：

```
1. 读 CURRENT_NOW → 按数值幅度判单位（≥100000 必是 µA，否则 mA）
2. 电压：EXTRA_VOLTAGE 落在 3000–5000 mV 才采信，否则按电量推算
3. 每个 getIntProperty 单独 try/catch（缺失属性会直接抛 SecurityException）
4. 充没充电看 EXTRA_STATUS + EXTRA_PLUGGED，不看电流符号
5. 拿不到的字段一律降级，不让主功能失效
```

这样做的好处是，OPPO 的联发科机型和骁龙机型节点布局完全不同，但同一份代码都能跑。

## 这也解释了为什么「通用充电功率 App」几乎不存在

同一个 App 在不同机器上能显示的内容完全不同：Pixel 上能拿到电压算准功率，OPPO 上电压是废值只能推算。AccuBattery 干脆绕开这件事，只报 `%/小时`。
